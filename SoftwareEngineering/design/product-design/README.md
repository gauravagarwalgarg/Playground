# Product Design

## Core Concepts

### User Stories
- Format: "As a [user type], I want [goal] so that [benefit]"
- Acceptance criteria: Specific, testable conditions for "done"
- INVEST: Independent, Negotiable, Valuable, Estimable, Small, Testable

### Wireframing & Prototyping
- **Low-fidelity**: Paper sketches, whiteboard → fast iteration
- **Mid-fidelity**: Wireframes (Balsamiq, Figma) → layout and flow
- **High-fidelity**: Interactive prototypes → user testing

### MVP (Minimum Viable Product)
- Smallest version that delivers value and enables learning
- Focus on core user journey, not features
- Build → Measure → Learn cycle
- Avoid: Feature creep, premature optimization, building without validation

### Iteration & Feedback
- Ship early, gather feedback, iterate
- Metrics: Engagement, retention, conversion, NPS
- A/B testing for data-driven decisions
- Qualitative: User interviews, usability testing

---

## Interview Talking Points

- Product design is about solving user problems, not building features
- Start with "why" (problem) before "what" (solution)
- Trade-offs: Speed to market vs. polish, breadth vs. depth
- Engineers should understand product context to make better technical decisions
